📚 What a Good Answer Looks Like
Binary search divides the search space in half each step: T(n) = T(n/2) + O(1) → O(log n). Best case O(1) occurs only when the target is the very first mid-element — not the average. On a reverse-sorted array, simply reverse the comparison logic (if target < mid, search right; if target > mid, search left).
Internal working of a HashMap — how does O(1) lookup work?

✗ Surface-level — hash function and bucket internals not explained
📚 What a Good Answer Looks Like
A hash function maps any key to an array index: index = hash(key) % array_size. Lookup jumps directly to that index → O(1). Collisions (two keys → same index) are handled by chaining (linked list at bucket) or open addressing (probe for next empty slot). Worst case (all keys collide) is O(n); with a good hash function, average is O(1).

📚 What a Good Answer Looks Like

📚 What a Good Answer Looks Like
Hoisting is JS's behaviour of moving declarations to the top of their scope before code execution. var declarations are hoisted and initialised as undefined — so you can reference them before the line they're declared. let and const are hoisted but NOT initialised (Temporal Dead Zone) — accessing them before declaration throws a ReferenceError. Function declarations are fully hoisted (both name and body). Function expressions are not.

📚 What a Good Answer Looks Like
Atomicity: a transaction is all-or-nothing — if any part fails, the whole transaction rolls back.
