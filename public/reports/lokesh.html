📚 What a Good Answer Looks Like
Boyer-Moore Voting Algorithm: initialise candidate = None, count = 0. For each element: if count == 0, set candidate = num. If num == candidate, increment count; else decrement. Final candidate is the majority element. Time O(n), Space O(1). Why it works: the majority element always outvotes all others combined.

📚 What a Good Answer Looks Like
O(n) approach: convert array to +1 (if element equals target) and -1 (otherwise). Compute prefix sums. A subarray [l, r] has majority element if prefix[r] - prefix[l-1] > (r-l+1)/2, which simplifies to counting prefix sums greater than half the length. Using a hashmap of prefix sum frequencies, this reduces to O(n) time, O(n) space.

✗ Incorrect — Virtual DOM confused with HTML DOM tree; reconciliation and real vs virtual DOM difference unknown
📚 What a Good Answer Looks Like
React's Virtual DOM is a lightweight in-memory representation of the real DOM. On state/prop change, React re-renders the virtual DOM and runs the reconciliation algorithm (React Fiber) — it diffs the new virtual DOM against the previous one and calculates the minimal set of real DOM operations needed. Only changed nodes are updated in the real DOM — far more efficient than re-rendering the whole page. Analogy: the virtual DOM is a blueprint; reconciliation decides what to repaint; the real DOM is the actual painted wall.

A Pure Component (React.PureComponent or a functional component wrapped in React.memo) only re-renders when its props or state actually change — it performs a shallow comparison. 📚 What a Good Answer Looks Like
JS primitives (number, string, boolean, null, undefined) are passed by value — a copy is made. Objects and arrays are passed by reference — the function receives a reference to the same object in memory (mutations affect the original). Pure functions: a function that (1) always returns the same output for the same inputs, and (2) has no side effects (doesn't modify external state, doesn't call APIs, doesn't mutate arguments). Example: const add = (a, b) => a + b. Used extensively in functional programming and React (reducers must be pure).

~ Partial — XOR ✓; binary search direction correct but precise condition not finalised
📚 What a Good Answer Looks Like
In a sorted array where all elements appear twice except one: use binary search on even indices only. At mid (force even): if nums[mid] == nums[mid+1], the unique element is to the right → lo = mid + 2. Else it's at mid or to the left → hi = mid. The mid^1 trick: XOR mid with 1 gives the paired index (if mid is even → mid+1; if mid is odd → mid-1). If nums[mid] == nums[mid^1], unique is in the right half. Time O(log n), Space O(1).
